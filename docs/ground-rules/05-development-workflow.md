# 개발 작업 흐름과 테스트

## 로컬

```text
C:\Users\able2\.gemini\antigravity\scratch\Portfolio
└─ 기존 HTML

C:\Users\able2\portfolio-react
└─ 새 React 프로젝트
```

## 작업 순서

1. 기준 브랜치를 최신 상태로 맞춥니다.
2. 목적에 맞는 작업 브랜치를 만듭니다.
3. 로컬에서 구현하고 실제 화면을 확인합니다.
4. 관련 파일만 커밋합니다.
5. PR에 변경사항, 테스트와 사용자 확인 항목을 작성합니다.
6. 기본 테스트 후 `beta`에 병합합니다.
7. `main`은 전용 승인 대화에서만 병합합니다.

## 기능 브랜치 기본 테스트

목표 시간은 10분 이내입니다.

- 프로덕션 빌드
- 코드 검사
- 변경 페이지 열기
- 심각한 콘솔 오류
- 변경한 주요 인터랙션
- Mobile 390px
- Desktop 1440px
- 변경 영역의 이미지와 링크

실패한 검사를 시간 제한 때문에 무시하지 않습니다. 10분 안에 해결되지 않으면 병합을 멈추고 원인과 추가 작업을 보고합니다.

## 반응형 테스트

기본 구현은 Desktop이며 같은 컴포넌트가 반응형으로 동작합니다. 별도 모바일 버전을 만들지 않습니다.

```text
Mobile: 390px
Tablet: 768px
Desktop: 1440px
```

기능 PR에서는 변경 페이지 중심으로 확인하고, `beta → main`에서는 주요 페이지 전체를 직접 브라우저로 확인합니다.

## 사용자와 개발자의 확인 범위

- 개발자: 빌드, 코드 검사, 실제 렌더링, 인터랙션, 콘솔과 반응형 기본 확인
- 사용자: 디자인 방향, 콘텐츠 의미와 최종 공개 승인

미확인 항목이 있으면 [`07-review-and-notifications.md`](07-review-and-notifications.md)를 따릅니다.

## 완료 기준

- 요구한 화면과 기능이 동작함
- 주요 반응형 화면이 깨지지 않음
- 파일과 컴포넌트 이름이 규칙에 맞음
- 임시 파일과 사용하지 않는 에셋이 없음
- 관련 페이지 README와 적용표를 확인함
- 빌드가 성공함
- 사용자 필수 확인 상태가 기록됨
