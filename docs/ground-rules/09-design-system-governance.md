# 디자인 시스템 운영 규칙

## 범위

디자인 시스템은 모든 페이지를 같은 모습으로 만드는 규칙이 아니라 반복되는 기반을 일관되게 관리하는 규칙입니다.

### 필수 적용

- 색상 체계
- 타이포그래피
- 간격과 Container
- 반응형 기준
- Focus와 접근성
- 공통 Header, Footer와 Button 동작

### Variant

디자인 시스템 안에서 의미가 명확한 선택지를 제공합니다.

```jsx
<Button variant="primary" />
<Container size="reading" />
```

### 페이지 전용 디자인

Home Hero, 프로젝트 갤러리와 Articles 편집 레이아웃처럼 페이지의 고유한 메시지를 표현하는 구성입니다. 페이지 전용이라는 이유만으로 디자인 예외가 되지는 않습니다.

### 디자인 예외

같은 역할에 적용해야 할 디자인 시스템 규칙을 의도적으로 벗어나는 경우입니다. 사용자 승인 없이 구현하지 않습니다.

## 디자인 예외 승인 절차

예외가 필요하다고 판단되면 코드를 작성하기 전에 채팅에 다음 경고를 표시합니다.

```text
⚠️ 디자인 예외 승인 필요

ID: DE-001
대상: [Home][Mobile] Hero 제목
기본 규칙: 모바일 h1은 type-heading-xl 사용
제안 예외: 한 단계 작은 type-heading-lg 사용
이유: 현재 문구가 세 줄로 갈라져 첫 화면의 정보 위계가 무너짐
영향 범위: Home Hero Mobile만
대안: 문구 단축 또는 Hero 레이아웃 변경
재검토 조건: Hero 문구나 레이아웃 변경 시

승인 전에는 구현하지 않습니다.
```

- 경고에는 대상 페이지와 화면 범위를 명시합니다.
- 기본 규칙, 제안 예외, 이유, 영향, 대안과 재검토 조건을 설명합니다.
- 사용자가 명시적으로 승인해야 진행합니다.
- 답변이 없으면 `필수 승인` 대기항목으로 등록하고 12시간·36시간 알림 규칙을 적용합니다.
- 단순한 “확인”이 승인인지 모호하면 다시 확인합니다.

## 승인 후 기록

승인된 예외에는 `DE-001` 형식의 고유 ID를 부여하고 다음 위치를 함께 갱신합니다.

1. 예외 코드 가까이의 `DESIGN-EXCEPTION` 주석
2. 해당 페이지 README의 디자인 예외 항목
3. [`docs/design-system/design-exceptions.md`](../design-system/design-exceptions.md)
4. 관련 PR의 사용자 승인과 변경사항
5. 사용자에게 보이는 릴리스라면 `versions/releases/vX.Y.Z.md`
6. 공통 컴포넌트 적용 상태와 관련되면 `component-adoption.md`

```css
/*
 * DESIGN-EXCEPTION [DE-001] [Home][Mobile]:
 * WHAT: Hero 제목을 모바일 기본 h1보다 한 단계 작게 표시
 * WHY: 세 줄 분리로 인한 정보 위계 붕괴 방지
 * APPROVED: 사용자 승인 완료
 * REVIEW: Hero 문구 또는 레이아웃 변경 시
 */
```

## 변경과 제거

- 승인 범위를 다른 페이지나 화면으로 자동 확장하지 않습니다.
- 예외 범위를 넓히려면 다시 경고하고 승인받습니다.
- 재검토 조건이 발생하면 예외를 유지, 수정 또는 제거할지 확인합니다.
- 예외가 반복되면 디자인 시스템의 새 Variant로 승격할지 페이지 완료 검토에서 논의합니다.
- 예외를 제거하면 중앙 목록 상태를 `Removed`로 바꾸고 제거 버전을 기록합니다.

## 디자인 시스템 변경 권한

- 화면 변화 없는 내부 정리: 개발자가 진행 후 보고
- 새 Variant: 영향 범위 설명
- 기존 토큰 값 변경: 영향 페이지 전체 표시 후 사용자 확인
- 기존 Variant 제거: 사용자 승인 필수
- 페이지 전용 디자인의 공통 규칙 승격: 페이지 완료 검토에서 결정
