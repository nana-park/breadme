# 콘텐츠와 다국어 관리 규칙

## 목표

동일한 문구와 데이터를 JSX에 반복해서 하드코딩하지 않습니다. 콘텐츠 원본을 한 곳에 두어 페이지 간 동기화와 한국어·영어 번역 상태를 관리합니다.

## 영역

```text
src/content/
├─ site/
├─ career/
├─ projects/
├─ articles/
└─ awards/

src/locales/
├─ ko/
└─ en/

src/config/
├─ navigation.ts
├─ routes.ts
└─ languages.ts
```

- `content`: 프로젝트, 경력, 수상과 아티클처럼 사용자에게 보이는 정보
- `locales`: 메뉴, 버튼, 오류 메시지처럼 반복되는 UI 문구
- `config`: 라우트, 언어와 동작 설정
- `pages`, `shared`: 콘텐츠를 표시하는 레이아웃과 인터랙션

## 파일 형식

- 짧고 구조화된 콘텐츠: 타입이 있는 TypeScript 객체
- 긴 프로젝트 본문과 아티클: 페이지를 개발할 때 Markdown 도입
- 복잡한 인터랙션과 시각 구성: JSX
- JSON은 주석을 지원하지 않으므로 기본 콘텐츠 형식으로 사용하지 않음

## 공통 메타데이터와 번역 분리

```text
src/content/projects/hopzie/
├─ metadata.ts
├─ ko.ts
└─ en.ts
```

`metadata.ts`에는 언어와 무관한 ID, slug, 날짜, 링크, 이미지와 공통 공식 명칭을 둡니다. `ko.ts`, `en.ts`에는 번역되는 제목, 설명, 역할, 성과와 이미지 설명을 둡니다.

동일 콘텐츠를 언어 파일에 복사하지 않습니다.

## 공통 명칭

브랜드, 제품, 기관, 기술처럼 번역하지 않거나 공식 표기를 유지하는 명칭은 [`docs/content/shared-terms.md`](../content/shared-terms.md)를 기준으로 관리합니다.

- 기준값은 영어입니다.
- 기준값이 영어라는 것은 사이트 기본 표시 언어가 영어라는 뜻이 아닙니다.
- 언어별 예외가 없으면 영어 기준값을 한국어와 영어 화면에서 함께 사용합니다.
- 공식 한국어 표기나 사용자 지정 예외가 있으면 해당 항목에만 `ko` 표시명을 추가합니다.
- 번역 여부가 애매하면 자동 번역하지 않고 사용자에게 확인합니다.
- 공통 명칭을 JSX나 각 언어 파일에 직접 반복하지 않습니다.

## 번역하지 않는 공통 데이터

- 콘텐츠 ID와 URL slug
- 이메일과 URL
- 날짜와 수치의 원본값
- 이미지와 파일 경로
- 기술명과 상표명
- 언어별 예외가 없는 공식 제품·브랜드·기관명

날짜와 수치는 원본값을 공유하고 화면 표시 형식만 언어별로 변환할 수 있습니다.

## 언어별 공식 표시명

공식 표기가 언어별로 다른 학교, 기관, 학위, 수상, 직책과 프로젝트명은 언어별 표시명을 관리합니다.

```js
{
  id: "sungkyunkwan-university",
  default: "Sungkyunkwan University",
  displayName: {
    ko: "성균관대학교",
    en: "Sungkyunkwan University",
  },
}
```

`displayName` 예외가 없으면 `default`를 사용합니다. 자동으로 추측해 번역하지 않습니다.

## 긴 콘텐츠

```text
src/content/articles/ai-accessibility/
├─ metadata.ts
├─ ko.md
└─ en.md
```

두 언어 본문을 한 파일에 섞지 않습니다. Markdown 도구는 Articles 또는 상세 페이지를 실제로 개발할 때 도입합니다.

## 상태

프로젝트, 아티클과 경력처럼 하나의 콘텐츠 단위에만 다음 상태를 적용할 수 있습니다.

```text
draft → review → approved → published
```

한국어 승인과 영어 승인은 별도로 관리합니다. 번역이 준비되지 않았을 때 다른 언어를 조용히 대신 표시하지 않습니다.

## 사용자 확인

다음 변경은 사용자 확인이 필요합니다.

- 소개 문구의 의미
- 역할, 기간과 성과 수치
- 회사·기관과 프로젝트 공식 명칭
- 외부 공개 여부와 링크 목적지
- 개인정보
- 번역 문구와 언어별 공식 표시명
- 공통 명칭 목록의 예외

명백한 오탈자, 띄어쓰기와 승인된 날짜 표시 형식 통일은 개발자가 수정 후 보고할 수 있습니다.

## 버전 기록

한국어와 영어는 별도 버전을 만들지 않습니다. 변경사항에 언어 범위를 명시합니다.

```text
- [Home][KO] Hero 소개 문구 수정
- [Home][EN] 직무명 번역 수정
- [Projects][KO][EN] 공통 제품명 수정
```

## 검증

페이지 완료와 릴리스 전 다음을 확인합니다.

- 필수 한국어·영어 키 누락
- 공통 명칭의 중복 하드코딩
- 콘텐츠 ID와 slug 일치
- 링크와 이미지
- 언어별 승인 상태
- 페이지 README의 콘텐츠 원본 링크
