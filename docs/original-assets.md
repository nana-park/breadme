# 원본 에셋 준비

## 기준과 범위

기존 `nana-park/Portfolio`의 다음 커밋에 들어 있는 원본 파일을 그대로 사용합니다.

- 저장소: https://github.com/nana-park/Portfolio
- 고정 커밋: `834815915647e4b3fbf9285b88b8001e37b94aa0`
- 목록: `src/content/original/asset-manifest.json`
- 준비 스크립트: `scripts/prepare-original-assets.mjs`
- 로컬 캐시: `public/original/`

매니페스트는 원래 경로, 파일 크기, SHA-256, 커밋이 고정된 다운로드 URL을 기록합니다. 현재 대상은 이미지·아이콘·PDF·영상 **147개, 289,373,612바이트(약 275.97 MiB)**입니다. HTML, CSS, JavaScript는 React 소스 이관 작업에서 따로 다루며 이 다운로드 대상에는 없습니다.

캐시는 Git에 커밋하지 않습니다. 대용량 원본을 새 Git 저장소에 중복으로 넣지 않고, 개발 또는 빌드 전에 준비해 방문자의 브라우저에는 같은 사이트의 정적 파일로 제공합니다. 원본 파일명에 공백, 대문자, 한글이 포함되어 있어도 경로와 바이트를 변경하지 않습니다. 이 캐시 경로는 원본과의 정확한 대응을 위한 의도적인 파일명 규칙 예외입니다.

전체 용량 중 Enjoy 사진 51개가 약 200.71 MiB입니다. 라우트와 이미지 지연 로딩으로 초기 다운로드를 줄일 수 있지만, 이 스크립트는 파일을 재압축하거나 다른 이미지로 바꾸지 않습니다.

## 실행

Node.js 24를 사용합니다. 프로젝트 최상위 폴더에서 실행합니다.

```sh
node scripts/prepare-original-assets.mjs
```

기존 HTML 저장소가 로컬에 있으면 먼저 그 파일을 사용합니다.

```sh
ORIGINAL_ASSET_SOURCE_DIR=/absolute/path/to/Portfolio node scripts/prepare-original-assets.mjs
```

PowerShell에서는 다음처럼 실행합니다.

```powershell
$env:ORIGINAL_ASSET_SOURCE_DIR = 'C:\path\to\Portfolio'
node scripts/prepare-original-assets.mjs
```

검증만 하려면 다음을 실행합니다. 파일을 쓰거나 다운로드하지 않습니다.

```sh
node scripts/prepare-original-assets.mjs --check
```

매니페스트와 필요한 개별 파일만 읽습니다. `.env` 파일, 토큰, 비밀번호, `.git`, 백업 디렉터리, 실행 파일은 읽지 않습니다. 선택적 환경 변수는 체크아웃의 경로만 받습니다.

## 다운로드와 캐시 동작

1. 기존 `public/original/` 파일의 크기와 SHA-256을 검사합니다.
2. 일치하면 그대로 재사용합니다. 정상 캐시에서는 네트워크 요청이 없습니다.
3. 캐시가 없거나 손상되었다면 지정된 로컬 체크아웃의 동일 경로 파일을 복사하고 검사합니다.
4. 로컬 원본이 없거나 고정된 해시와 다르면 `raw.githubusercontent.com`의 해당 커밋에서 다운로드합니다. 로컬 체크아웃 경로 자체가 존재하지 않으면 설정 오류로 중단합니다.
5. 다운로드와 준비 작업은 최대 4개씩 실행하며, 각 요청에는 60초 제한이 있습니다.
6. 검증을 통과한 임시 파일만 최종 경로로 원자적으로 옮깁니다. 크기 초과·해시 불일치·HTTP 오류는 실패로 처리합니다.
7. 실패가 하나라도 있으면 종료 코드가 0이 아니므로 빌드를 중단해야 합니다. 이미 검증된 파일은 다음 실행에서 재사용합니다.

경로 이동(`..`), 숨김 파일, 미지원 확장자, symlink, 지정 저장소·커밋 밖의 다운로드 URL을 거부합니다. 사용하지 않는 파일을 자동 삭제하지 않습니다. 원본을 업데이트할 때는 매니페스트의 커밋·크기·해시를 함께 검토해 변경합니다.

CI에서는 이 준비 단계를 프로덕션 빌드 전에 실행합니다. `public/original/`을 매니페스트 해시 기준으로 캐시하면 반복 다운로드를 줄일 수 있습니다. 최종 빌드 산출물에는 정적 파일이 포함되므로 배포 시스템에도 약 276 MiB의 원본 에셋을 수용할 공간이 필요합니다. 로컬 캐시와 `dist/`를 동시에 보관하면 공간이 추가로 필요합니다.

브라우저 경로는 `/original/{원래 경로}`이며, 하위 경로 배포에서는 애플리케이션의 Vite base-aware 경로 도우미를 통해 만듭니다. 로컬 파일시스템 경로나 GitHub raw URL을 화면의 `src`로 직접 넣지 않습니다.

## 누락 및 외부 리소스

`og-thumbnail.jpg`는 원본 OG 메타데이터에 쓰여 있지만 기준 커밋에는 없습니다. 매니페스트의 `missingSourceAssets`에 기록했고 임의 대체 이미지를 만들지 않았습니다.

매니페스트의 `pendingExternalAssets`에는 다음 **68개 외부 리소스**를 별도로 기록합니다.

- ART insight 본문 이미지 47개
- Hopzie 아바타 이미지 5개와 대체 이미지 URL 5개
- mentoring mockup의 Gmail 아이콘 1개
- Google Fonts 및 Pretendard CSS 5개
- Tailwind 및 Spline viewer 스크립트 2개
- 원본 Spline 장면 1개
- YouTube API 및 iframe 2개

이 스크립트는 원본 Git 저장소 안의 147개 파일만 담당합니다. 외부 URL의 실제 파일은 `prepare-external-assets.mjs`와 별도 매니페스트가 담당하며 **211개가 확보·해시 검증 완료**되었습니다. `pendingExternalAssets`는 초기 조사에서 사용한 필드 이름이며 현재 미확보 상태를 뜻하지 않습니다.

자세한 글꼴·사진·Spline 원본, 라이선스와 고정 아바타 처리 방식은 [외부 원본 파일 기록](original-external-assets.md)을 참고하세요. YouTube 같은 외부 서비스 플레이어는 정적 이미지 캐시와 구분하여 검수합니다.

원본 147개는 GitHub Actions의 비어 있는 캐시에서도 모두 다운로드·해시 검증에 성공했습니다(2026-10-04). 파일을 이미 받았다면 다음 실행은 검증 후 재사용합니다.

## 출처와 이용 조건

이 매니페스트는 사용자가 요청한 본인 포트폴리오의 원본 스타일 이관을 위해, 위 저장소의 지정 커밋에 이미 포함된 파일을 추적합니다. 원본 루트에서 별도 LICENSE 파일은 발견하지 못했습니다. 매니페스트 작성이나 캐시 다운로드가 새로운 이용 허가를 부여하지 않습니다.

제3자 로고, 논문 PDF, 폰트, 기사 이미지, Spline 장면, 영상에는 각 권리자의 조건이 적용될 수 있습니다. 출처를 유지하고 원본 목적 범위를 벗어난 재배포·라이선스 부여를 가정하지 않습니다. 기존 사이트와 원본 저장소를 변경하거나 공개 배포하지 않습니다.

## 외부 파일도 확보 완료

이 문서의 147개는 원본 Git 저장소 안의 파일만 세는 숫자입니다. 글꼴·아티클 이미지·Spline 장면/배지는 [외부 원본 파일 기록](original-external-assets.md)의 211개가 별도로 확보·검증되었습니다. 두 준비 스크립트가 함께 실행되며 방문자에게는 로컬 파일로 제공됩니다. 기존 목록의 외부 항목은 미확보 상태를 뜻하지 않습니다.
