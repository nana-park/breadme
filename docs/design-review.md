- 검토일: 2026-10-04
- 기준 브랜치: `docs/collaboration-ground-rules`
- 기준 커밋: `4b07328` (`docs: require shared term checks`)
- 기준 상태: 문서·설정 22개 파일이 있으며 React 실행 앱은 아직 없는 상태
- 작업 목적: 기존 설계 규칙을 바탕으로 Home 미리보기와 반응형 React 기본 구조를 만들기

검토한 자료는 협업·구조·스타일 운영 규칙입니다. 확정된 세부 화면 시안이나 완성된 디자인 토큰 명세를 확인한 것으로 보지 않습니다. 이번 미리보기의 원본 white/black/orange 계열 색상·간격은 구조를 확인하기 위한 출발점이며 최종 브랜드 디자인 승인을 뜻하지 않습니다.

## 1. 유지하는 설계 원칙

| 기존 원칙 | 이번 기본 구조에 적용하는 방법 |
| --- | --- |
| 기존 HTML과 이력 보존 | [기존 원본 저장소](https://github.com/nana-park/Portfolio)를 수정하거나 백업 폴더로 복제하지 않습니다. React 작업을 별도로 진행합니다. |
| 페이지 중심 구조 | Home의 주요 영역을 페이지 가까이에 두고 공통 레이아웃과 UI만 `shared/`에서 사용합니다. |
| 콘텐츠와 레이아웃 분리 | 콘텐츠·반복 UI 문구·동작 설정을 각각 `content/`, `locales/`, `config/`에 둡니다. |
| 전역 CSS와 CSS Modules | 전역에는 초기화·토큰·기본 타이포그래피를 두고, 각 컴포넌트가 배치와 반응형 스타일을 소유합니다. |
| 동일 컴포넌트의 반응형 | 데스크톱을 기본으로 태블릿·모바일 스타일을 적용합니다. 핵심 정보나 기능을 기기별로 분리하지 않습니다. |
| 기획자가 읽을 수 있는 설명 | 주요 섹션에 WHAT, 자명하지 않은 선택에 WHY를 기록합니다. README는 화면과 수정 위치를 쉬운 말로 설명합니다. |
| 승인된 콘텐츠와 디자인 보호 | 새로운 성과·경력·번역·공식 명칭을 추측하지 않으며, 승인된 디자인 예외가 없는 현재 상태를 유지합니다. |

## 2. 문서 사이의 차이와 적용 결정

### 콘텐츠 위치: `src/data/`와 `src/content/`

`06-code-organization-and-comments.md`에는 작업 시작 시 자주 바뀌는 정보를 `src/data/`에 두는 예시가 남아 있었습니다. 반면 폴더 구조를 정한 `02`와 콘텐츠 전용 규칙인 `10`은 `src/content/`를 명시합니다.

**결정:** 더 구체적인 폴더·콘텐츠 규칙에 맞춰 `src/content/`를 사용합니다. `src/data/`를 추가하거나 같은 내용을 두 곳에 복사하지 않습니다. 기존 규칙 파일의 해당 예시도 같은 변경에서 `src/content/`로 수정했습니다.

### 파일 확장자: JSX·JS 예시와 TypeScript

기존 문서는 `HomePage.jsx`, `main.jsx`, `terms.js` 같은 JavaScript 예시를 사용합니다. 이름·역할·소유권에 관한 규칙은 유지하면서 이번 실행 앱은 Vite, React, TypeScript를 사용합니다.

**결정:** React 화면은 `.tsx`, 일반 코드와 구조화된 콘텐츠는 `.ts`를 사용합니다. 타입은 콘텐츠 항목이나 메뉴 목적지의 누락을 개발 중 확인하기 위한 장치입니다. 폴더 구조, PascalCase 컴포넌트, camelCase 콘텐츠 파일, `.module.css` 규칙은 그대로 적용합니다. 예를 들어 기존 `terms.js`의 역할은 `src/content/shared/terms.ts`가 담당합니다.

### 문서의 목표 구조와 이번 실제 구현

기존 문서에는 여러 페이지, 영어 콘텐츠, 라우트와 상세 본문을 위한 장기 구조가 있습니다. 파일명이 예시로 있다는 이유만으로 빈 페이지나 동작하지 않는 메뉴를 만들지 않습니다.

**결정:** 이번에는 Home 하나와 소개·프로젝트·연락 영역을 만듭니다. 실제로 존재하는 영역에 기본 앵커 링크를 연결합니다. 상세 페이지나 두 번째 언어가 필요해지는 시점에 라우팅·Markdown·번역 도구를 검토합니다.

### 버전 허브의 작업 브랜치

기준 문서의 작업 브랜치는 `feature/home-design-system`입니다. 이는 이전 목표를 가리키므로 이번 반응형 기본 구조의 실제 작업 브랜치와 구분해야 합니다.

**결정:** 이번 브랜치는 규칙의 `feature/` 접두사를 따르는 `feature/responsive-react-foundation`입니다. 버전 허브와 변경 이력은 실제 작업 범위·검증·확인 상태에 맞춰 갱신해야 합니다. 새 문서 검토만으로 기능 완료나 공개 준비 완료를 표시하지 않습니다.

## 3. 이번 구현 범위

### 포함

- Vite·React·TypeScript 실행 기반과 필요한 코드·타입·빌드 검사
- Home 미리보기, 공통 레이아웃과 의미 있는 HTML 제목 구조
- 중립적인 디자인 토큰, CSS Modules, 3개 화면 구간의 스타일
- 하나의 내비게이션과 키보드로 조작 가능한 모바일 펼침 메뉴
- 화면 내용, 한국어 UI 문구와 내비게이션 설정의 분리
- 비개발자도 실행 방법과 수정 위치를 찾을 수 있는 README
- [반응형 전략과 자체 QA 확인표](responsive-strategy.md)

### 후속 콘텐츠 작업으로 남김

- 프로젝트·경력·성과·기간·연락처 전체 이관과 의미 검토
- About·Projects·Research·Articles·Lectures·Awards·Contact의 별도 페이지
- 승인된 영어판과 언어 전환, 긴 본문을 위한 Markdown 도입
- 프로젝트 필터, 연락 폼, 백엔드, 로그인, 외부 분석 서비스
- 원본 이미지·영상 전체 이전, 최종 브랜드 디자인과 실제 성능 측정

향후 항목은 이번 화면에서 구현된 기능처럼 보여 주지 않습니다. 원본에 있는 내용을 삭제하거나 공개 범위를 새로 결정하는 작업도 포함하지 않습니다.

## 4. 화면 문구와 승인 경계

- 원본 `breadme` 워드마크(orange/black), 이름 `Nahyun Park`와 원본 `index.html`의 Hero 문구 `Designing Actionable AI`, `AI PRODUCT MANAGER · UX RESEARCH · PSYCHOLOGY`를 유지합니다.
- 영어 원문은 임의로 번역하거나 직무·포지셔닝 의미를 바꾸지 않습니다. 한국어 문서 안에서 이 영어 원문과 코드 이름을 유지하는 것은 공식 명칭과 원본 보존을 위한 것입니다.
- UI는 한국어이며, 영어 원문에는 해당 언어를 표시합니다. 원본 영어 Hero를 재사용했다고 영어판 전체가 승인된 것으로 보지 않습니다.
- 프로젝트와 연락 영역에는 콘텐츠 준비 상태를 명시합니다. 검증하지 않은 회사·협업사·프로젝트·성과 수치를 채워 넣지 않습니다.
- 기존 내용을 확인할 수 있는 [공개 원본 포트폴리오](https://nana-park.github.io/Portfolio/) 링크를 제공합니다. 원본 `index.html`의 메타데이터와 같은 홈페이지 주소를 사용하며, 새 React 상세 페이지가 준비된 것처럼 링크를 만들지 않습니다.
- 앞으로 소개 문구의 의미, 역할·기간·성과, 공식 명칭, 개인정보, 번역, 링크 목적지나 공개 범위를 바꿀 때는 해당 사용자 확인 절차를 따릅니다.

## 5. 채용 담당자의 화면별 경험

동일한 경험은 두 화면을 같은 모양으로 만드는 뜻이 아닙니다. 데스크톱에서는 구역을 빠르게 훑고, 모바일에서는 같은 내용을 순서대로 읽으며 같은 행동을 할 수 있는 상태입니다.

- 핵심 정보의 순서와 목적지는 같습니다.
- 모바일에서도 중요한 설명과 행동을 숨기지 않습니다.
- 카드의 가로 슬라이드나 Hover에만 있는 정보에 의존하지 않습니다.
- 메뉴를 펼치거나 접는 방식만 화면 여건에 맞춥니다.
- 320px 재배치, 200% 글자 확대, 44px 조작 영역, 키보드·초점·이동 줄이기를 검사 기준으로 둡니다.

구체적인 너비별 확인 항목과 메뉴 전환 검사는 [반응형 전략](responsive-strategy.md#7-자체-qa-확인표)에 기록합니다.

## 6. 검증과 완료 판정

이 검토 문서는 설계 결정과 검사 계획의 기록입니다. 작성 시점에 실행하지 않은 빌드·테스트·브라우저 검사를 통과로 표시하지 않습니다.

완료 보고에서는 다음을 나눠 기록해야 합니다.

1. **문서와 구조 확인:** 규칙 준수, 콘텐츠 원본 위치, 페이지 README, 공통 컴포넌트 적용표, 디자인 예외 여부
2. **개발 검사:** 코드 검사, 타입 검사, 자동 테스트, 프로덕션 빌드의 개별 실행 결과
3. **실제 화면 확인:** 320·390·767·768·1024·1025·1440px, 키보드, 확대, 메뉴 Escape·너비 전환·뒤로 이동
4. **확인하지 못한 범위:** 실제 기기, 다른 브라우저, 보조 기술 또는 콘텐츠가 아직 없는 기능
5. **사용자 판단이 필요한 항목:** 최종 디자인, 콘텐츠 의미, 언어별 승인과 공개 여부

자동 테스트가 성공해도 최종 시각 디자인 승인이나 전체 콘텐츠 이관 완료로 보지 않습니다. 문제가 발견되면 실패한 항목, 수정 내용과 재검사 결과를 함께 남깁니다.

## 7. Git과 공개 범위

- 문서 브랜치의 기존 커밋을 유지한 채 `feature/responsive-react-foundation`에서 작업합니다.
- 이번 검토용 Draft PR은 `docs/collaboration-ground-rules`를 대상으로 합니다. 일반적인 기능 → `beta` 흐름을 바꾸는 상시 규칙은 아닙니다.
- 이번 범위에서 브랜치를 병합하거나 운영 사이트에 배포하지 않습니다.
- 특히 `main` 반영은 기존 규칙대로 별도의 명시적 승인 절차가 필요합니다.
