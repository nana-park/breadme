# 원본 디자인을 보존하는 반응형 전략

> 범위 안내 (2026-10-05): 이 문서는 최초 원본 이관 시점의 전략·검수 범위를 보존합니다. 이후 PR #2에서 Home은 텍스트 중심으로 바뀌어 **Spline을 렌더링하지 않으며**, PR #3 이후 767px 이하 최소화 자료 바로가기는 **Hero 이후에도 숨깁니다**. 아래 Spline 유지/배치와 검사 수치는 당시 기준입니다. 현재 Home·모바일 읽기/메뉴 경계는 [디자인 안내](design-system/README.md), [Home README](../src/pages/home/README.md), 최신 검수 절차는 [QA 안내](qa/README.md)를 따릅니다. 원본 콘텐츠 보존·같은 조건 비교·승인 없이 재설계하지 않는 일반 원칙은 유지합니다.

## 최초 이관 기준 (2026-10-04)

2026-10-04, 사용자가 요청한 **원본 스타일의 데스크톱·모바일 React 이관**을 기준으로 합니다. 원본은 `nana-park/Portfolio@834815915647e4b3fbf9285b88b8001e37b94aa0`입니다.

초기의 Home 구조 미리보기는 실제 포트폴리오 화면으로 교체했습니다. 당시의 한국어 안내·앵커 3개·CSS Modules 중심 새 뼈대는 현재 화면의 기준이 아닙니다. [초기 설계 검토](design-review.md)와 [초기 검수 기록](qa/foundation-verification.md)은 변경 과정을 남기는 역사 자료입니다.

채용 담당자는 어느 화면에서도 같은 경력·프로젝트·본문·연락 경로를 이용할 수 있어야 합니다. 화면이 작다는 이유로 원본 내용을 새 요약으로 바꾸거나 별도 모바일 콘텐츠를 만들지 않습니다.

## 1. 옮긴 화면과 콘텐츠

- 핵심 화면 11개: Home, About, Career, Qualified, Enjoy, Projects, Research, Articles, Lectures, Awards, Contact
- 연결된 프로젝트 상세 3개: Voice IVR, Hopzie, AI Mentoring
- Articles: 원본 영어 본문 18개, 6쪽 목록, 읽기와 뒤로·앞으로 이동
- 원본의 글꼴·색·간격·SVG·사진·영상·Spline 장면과 표시 배지
- 경력 전환, 인증 탭, 갤러리, 강의 캐러셀, 프로젝트 펼침과 상세 탭

총 14개 페이지 단위이며 `/`와 `/index.html`은 같은 Home입니다. 경로와 화면별 구성은 [원본 이관 페이지 설명](../src/pages/original/README.md)에 있습니다. 원본에서 숨긴 Enjoy 메뉴는 숨긴 채 기존 주소의 화면을 유지합니다. 연결되지 않은 예전 상세 페이지·백업은 이관 대상에 포함하지 않습니다.

화면은 실제 React JSX입니다. 전체 HTML을 iframe이나 HTML 문자열 주입으로 감싸지 않습니다. 원본의 YouTube 플레이어는 미디어 임베드로 유지하고, 멘토링 제품 데모는 React 요소로 옮깁니다.

## 2. 데스크톱은 원본과 같은 조건으로 비교

- 같은 너비에서 원본과 React의 글꼴, 글자 크기, 위치, 여백, 이미지 비율과 섹션 순서를 대조합니다.
- 원본 디자인을 새 색상·카드·레이아웃으로 다시 만들지 않습니다.
- 원본 CSS와 utility의 적용 순서를 유지합니다. 순서를 바꿔 발생한 시각 차이를 새 디자인으로 정당화하지 않습니다.
- 원본 Spline 장면과 표시 배지를 유지합니다. 움직이는 3D의 회전 프레임 차이는 정적 레이아웃 차이와 나누어 검토합니다.
- 원본에 있는 가로 갤러리와 강의 캐러셀도 유지합니다. 모바일에서 읽고 조작할 수 있는지는 별도로 확인합니다.

초기 협업 문서는 CSS Modules 중심의 새 구조를 설명합니다. 현재 이관은 사용자가 요청한 원본 재현을 위해 **원본 작성 CSS → 페이지 CSS → 원본 Tailwind utility → 필요한 모바일·접근성 보정** 순서를 보존합니다. Tailwind utility는 로컬에서 생성합니다. 이 이관 방식을 이후 모든 신규 화면의 스타일 규칙으로 자동 확대하지 않습니다. 스타일 재구성은 원본 대조가 끝난 뒤 별도 범위로 판단합니다.

## 3. 모바일은 필요한 사용성 보정만 적용

모바일에서도 원본의 표현과 내용은 같습니다. 화면 밖으로 잘리는 요소, 버튼 겹침, 터치·키보드 접근처럼 사용을 막는 부분을 보정합니다.

- Home의 좁은 화면에서 3D가 과도하게 잘리지 않도록 표시 영역을 맞춥니다.
- 자료 버튼이 Hero 문구나 주요 CTA를 가리지 않게 조정합니다.
- 메뉴·자료 조작 버튼은 모바일에서 44px 조작 영역을 확보하도록 보정합니다. 모든 원본 링크가 검증된 것으로 확대 해석하지 않습니다.
- 원본의 열·탭·캐러셀 구조를 무조건 한 열 목록으로 대체하지 않습니다.
- 필수 정보가 Hover에서만 접근 가능하지 않은지 확인합니다. 데스크톱 하위 메뉴는 키보드 초점으로도 열리고 모바일에서는 항목을 직접 이용할 수 있게 합니다.
- 실제 가로 넘침과 장식 영역의 의도된 잘라내기를 구분합니다. 본문이나 기능이 보이지 않는 결함을 단순히 숨기지 않습니다.

### 너비별 기준

모든 수치는 브라우저 표시 영역의 CSS 픽셀입니다. 원본 페이지의 개별 반응형 규칙은 유지하므로 모든 영역을 한 가지 경계로 강제하지 않습니다.

| 대상 | 최초 이관 당시 기준 |
| --- | --- |
| 공통 Header | 높이 70px, **1024px 이상** 데스크톱 메뉴 |
| 공통 모바일 메뉴 | **1024px 미만**에서 메뉴 버튼과 전체 높이의 펼침 영역 |
| 추가 좁은 화면 보정 | **767px 이하**, Home Spline·CTA·자료 UI 등 필요한 부분 |
| 원본 페이지 배치 | 원본 CSS와 utility가 가진 경계를 유지하고 실제 화면으로 확인 |

초기 뼈대의 767↔768px 메뉴 전환과 현재 Header의 1023↔1024px 전환은 다릅니다. 초기 QA 결과를 현재 메뉴의 검수 근거로 사용하지 않습니다.

## 4. 메뉴·주소·초점

- 원본 `.html` 경로와 일반 링크 이동을 유지합니다. 주소 직접 입력과 새로고침도 검사합니다.
- Articles는 원본 `#article-detail?id=…` 주소와 목록 복귀를 유지합니다.
- 모바일 메뉴는 화면을 덮는 동안 배경을 조작할 수 없게 하고, 초점을 메뉴 안에서 순환시킵니다. 메뉴를 닫으면 기존 스크롤과 배경의 조작 상태를 복원합니다.
- Escape와 메뉴 버튼으로 반복해서 닫을 수 있고, 닫은 뒤 메뉴 버튼으로 초점이 돌아가는지 확인합니다.
- 1023↔1024px로 바꿀 때 숨겨진 버튼·링크에 초점이 남지 않도록 보이는 대응 요소로 옮깁니다. 본문에 있던 초점은 불필요하게 가져오지 않습니다.
- 데스크톱 하위 메뉴는 Escape로 닫고 상위 항목으로 초점을 돌려줍니다.
- 자료 패널은 메뉴와 달리 비모달입니다. 열기·최소화·닫기·메뉴와의 겹침을 별도로 검사합니다.
- 본문 바로가기와 보이는 초점 표시를 제공합니다. 원본 제목 구조도 확인하되 구조를 검사했다고 전체 접근성이 인증된 것으로 보지 않습니다.

## 5. 원본의 준비 중 상태도 보존

현재 화면 언어는 원본 영어이며 문서 언어는 한국어입니다. 초기 한국어 구조 안내 화면은 더 이상 현재 UI를 설명하지 않습니다.

- 원본 Korean 버튼의 `Coming soon!` 안내를 유지합니다. 번역이 끝난 것처럼 표시하지 않습니다.
- 이력서·포트폴리오 자료 요청은 `Coming Soon` 상태이며 전송 입력을 비활성화합니다.
- 자료 전송 백엔드나 메일 자동 발송은 없습니다. 성공 메시지로 전송을 흉내 내지 않습니다.
- 기존 공개 연락 링크는 원본대로 유지합니다. 새로운 개인정보·경력·성과 수치를 만들어 넣지 않습니다.
- 원본에 있던 문구 오류·깨진 문자를 확인 없이 추측해 고치지 않습니다. 콘텐츠 교정과 새 번역은 별도 검토합니다.

## 6. 파일과 성능

원본 에셋 **147개**와 외부 파일 **211개**를 고정된 매니페스트의 길이·SHA-256으로 검증합니다. 처음 준비하는 파일은 합계 **약 302 MiB**입니다. 이는 개발·빌드 캐시 전체 용량이며 방문자 한 번의 페이지 로드 전송량을 뜻하지 않습니다.

- 원본 이미지·영상 약 276 MiB와 외부 글꼴·이미지·장면 등 약 26 MiB를 로컬 정적 파일로 제공합니다.
- 큰 파일을 React Git 이력에 중복 저장하지 않고 `public/original/`, `public/original-external/`에서 재사용합니다.
- 원본을 비슷한 이미지로 바꾸거나 검수 전에 임의 재압축하지 않습니다.
- 원본 기본 아바타 5개는 검증한 바이트를 고정해 복원하며 해시 검사를 유지합니다.
- 실제 페이지 로딩·메모리·레이아웃 이동은 별도 측정 대상입니다. 파일 무결성 통과를 성능 통과로 표시하지 않습니다.
- 추후 이미지 압축·반응형 이미지·지연 로딩을 바꿀 때도 원본 시각 결과와 핵심 콘텐츠를 함께 확인합니다.

자세한 준비·복구·라이선스 설명은 [원본 에셋](original-assets.md)과 [외부 파일](original-external-assets.md)에 있습니다.

## 7. 최초 이관 당시 검수 범위와 확인표

2026-10-04 문서 갱신 시점: 로컬 lint·typecheck·단위 테스트 **68개**·build 통과를 확인한 상태입니다. 통합 브라우저 검사 **48개는 2801632에서 모두 통과**했습니다. 마지막 Enjoy 보정·문서 커밋의 결과는 PR checks에 연결됩니다. 최신 결과와 정확한 커밋은 [이관 검수 기록](qa/original-migration-verification.md)과 [디자인 비교](../design-qa.md)를 기준으로 확인합니다.

### 완료 여부를 별도로 기록할 항목

- 코드·타입·단위·빌드의 개별 결과와 전체 브라우저 검사 결과
- 경력·인증·갤러리·강의·프로젝트 펼침·상세 탭의 실제 동작
- 모바일 메뉴의 반복 열기·Escape·Tab 순환·너비 전환·초점·스크롤 복원
- 자료 UI의 비활성 전송 상태와 메뉴·CTA 겹침
- 직접 주소·새로고침·브라우저 뒤로·앞으로와 아티클 목록 복귀
- 키보드 사용, 좁은 화면, 글자 확대 200%, 실제 브라우저 줌의 각각의 확인 범위
- reduced motion에서 이동 효과 완화. 외부 3D·미디어까지 모두 정지한다고 가정하지 않기
- 콘솔 오류, 깨진 리소스와 링크, 원본 대조 캡처

초기 뼈대에서 확인한 200% 루트 글꼴 확대나 자동 접근성 결과는 현재 14개 페이지에 승계하지 않습니다. 실제 iOS·Android 기기, Safari·Firefox, 스크린리더 전체 검수와 브라우저 자체 줌은 아직 수행하지 않은 범위입니다. 자동 검사·스크린샷과 실제 기기 검수는 구분합니다.
