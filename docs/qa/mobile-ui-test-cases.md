# 모바일 UI·가독성 테스트 케이스

## 무엇을 확인하나요?

휴대폰에서 각 메뉴를 처음 열었을 때 제목·설명을 읽고 다음 행동을 할 수 있는지 확인합니다. 화면 전체의 가로 넘침뿐 아니라 글자 자체의 잘림, 버튼끼리의 겹침, 작은 조작 영역, 긴 글과 펼친 내용도 검사합니다.

- 기준 공개 버전: `4f026a3`.
- 폭: 320, 360, 375, 390, 430, 767, 768px. 데스크톱 비교 기준은 1440px입니다.
- 캡처 환경: GitHub Actions의 Chromium. 실제 휴대폰·iOS Safari를 시험했다는 뜻은 아닙니다.
- 글자 확대: 루트 글꼴을 200%로 설정하는 별도 상태입니다. 브라우저 자체 확대와 구분합니다.
- 첫 진단에서는 화면과 측정값을 저장합니다. **캡처 성공은 UI 합격을 뜻하지 않습니다.** 실제로 본 문제에만 회귀 조건을 추가합니다.

## 공통 실행·판정 방법

1. 경로를 열고 글꼴과 첫 화면 이미지를 기다립니다.
2. 정해진 폭에서 첫 화면을 캡처하고 글자·요소 위치를 기록합니다.
3. 문구 전체를 읽을 수 있는지, 제목/본문/보조 정보의 크기 차이가 자연스러운지 봅니다.
4. 메뉴·버튼·탭은 화면에 보이는 상태와 실제 클릭 영역을 함께 확인합니다.
5. 수정 전·후 같은 폭과 상태를 비교합니다. 최종 결과에는 확인된 문제와 남은 한계를 구분합니다.

작은 캡션이나 제품 설명용 축소 모형의 글자를 실제 본문과 같은 기준으로 무조건 확대하지 않습니다. 독립적인 조작 버튼은 44×44px를 목표로 하며 예외가 있으면 해당 TC에 이유를 남깁니다.

## 결과 기록

현재는 새 캡처를 실행하기 위한 TC 준비 단계입니다. 아직 실제 UI 문제를 확정하거나 수정 후 합격으로 표시하지 않았습니다. 후속 검수에서 각 확인 항목의 수정 전·후 상태와 정확한 커밋·CI 링크를 여기에 기록합니다.
