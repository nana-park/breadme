# 모바일 UI·가독성 테스트 케이스

## 무엇을 확인하나요?

휴대폰에서 각 메뉴를 처음 열었을 때 제목·설명을 읽고 다음 행동을 할 수 있는지 확인합니다. 화면 전체의 가로 넘침뿐 아니라 글자 자체의 잘림, 버튼끼리의 겹침, 작은 조작 영역, 긴 글과 펼친 내용도 검사합니다.

- 기준 공개 버전: `4f026a3`.
- 폭: 320, 360, 375, 390, 430, 767, 768px. 데스크톱 비교 기준은 1440px입니다.
- 캡처 환경: GitHub Actions의 Chromium. 실제 휴대폰·iOS Safari를 시험했다는 뜻은 아닙니다.
- 글자 확대: 루트 글꼴을 200%로 설정하는 별도 상태입니다. 브라우저 자체 확대와 구분합니다.
- 첫 진단에서는 화면과 측정값을 저장합니다. **캡처 성공은 UI 합격을 뜻하지 않습니다.** 실제로 본 문제에만 회귀 조건을 추가합니다.

## 공통 실행·판정 방법

1. 경로를 열고 글꼴과 첫 화면 이미지를 기다립니다.
2. 정해진 폭에서 첫 화면을 캡처하고 글자·요소 위치를 기록합니다.
3. 문구 전체를 읽을 수 있는지, 제목/본문/보조 정보의 크기 차이가 자연스러운지 봅니다.
4. 메뉴·버튼·탭은 화면에 보이는 상태와 실제 클릭 영역을 함께 확인합니다.
5. 수정 전·후 같은 폭과 상태를 비교합니다. 최종 결과에는 확인된 문제와 남은 한계를 구분합니다.

작은 캡션이나 제품 설명용 축소 모형의 글자를 실제 본문과 같은 기준으로 무조건 확대하지 않습니다. 독립적인 조작 버튼은 44×44px를 목표로 하며 예외가 있으면 해당 TC에 이유를 남깁니다.

## 확대·상태 검사의 구분

- `root-font-200`: 루트 글자 크기를 2배로 설정합니다. px로 지정된 원본 본문까지 자동으로 커지지는 않습니다.
- `synthetic-text-200`: 해당 HTML 영역의 실제 계산된 글자 크기와 숫자 줄간격을 각각 2배로 설정합니다. 원래 크기를 먼저 고정해 부모/자식이 중복 확대되지 않게 합니다.
- 두 방법 모두 브라우저 자체 확대·OS 글자 크기·실제 Safari 시험을 대신하지 않습니다.
- 18개 글은 390px에서 제목·중간 본문·출처/목록 복귀 영역을 캡처합니다. 대표 긴 제목은 8개 폭을 추가 확인합니다. 모든 글을 모든 폭에서 검사했다는 뜻은 아닙니다.
- 비기본 상태는 Qualified 4개 탭, Projects 펼침, 상세 3개의 탭·비교표 가로 이동, 강의 사진, Career의 활성 카드들을 구분합니다.

## 데스크톱·경계 화면 보호

`playwright.desktop-unchanged.config.ts`는 불변 main `4f026a3`을 별도 빌드해 같은 Chromium·같은 폰트·같은 에셋에서 후보와 비교합니다. 14개 경로 × 768/1440px × 첫 화면/전체 Footer의 56개 PNG 픽셀 비교입니다. 픽셀 차이를 허용하지 않습니다.

동영상·iframe·canvas 등 동적 미디어 픽셀은 양쪽에서 동일하게 숨기며 그 영역의 기하 정보는 별도로 비교합니다. 따라서 이 결과는 전체 긴 페이지·모든 상호작용 상태·실제 동영상 프레임의 데스크톱 동일성 주장이 아닙니다. 모바일 전용 규칙이 768px 이상에 새는지 검출하는 범위입니다.

최종 수정 후 화면과 정확한 검수 커밋/결과는 [PR #3](https://github.com/nana-park/breadme/pull/3)에 연결합니다. Draft PR은 병합·배포 승인이 아닙니다.

## 명시적 보류 항목

AI Mentoring 상세의 원본 JSX 파일은 공개 기준 `4f026a3`과 동일하게 유지합니다. 기존 데모 예시 데이터가 포함된 전체 파일 업로드가 허용되지 않아, 선택적인 제목/Director’s Log 글자 역할 표식 2개는 이번 수정에서 제외했습니다. 그 경로의 기존 제목 32px·설명 14px는 새 30–36/16px 규칙을 적용했다고 표시하지 않습니다. 공통 메뉴·Footer 수정과 경로/동작 검사는 그대로 포함합니다. 이 항목을 숨기거나 전체 글자 크기 개선 완료로 보고하지 않습니다.
