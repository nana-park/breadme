## 조작·상태 확인

- 단일 h1, 명확한 이관 대기 안내와 실제 앵커 목적지
- 주요 링크·버튼의 최소 44×44px 조작 영역
- 메뉴를 반복해서 열고 닫기, Escape 후 메뉴 버튼으로 포커스 복귀
- 메뉴 항목 선택 후 닫기와 목적지 영역 포커스
- 767↔768px 전환에서 숨겨지는 버튼/링크 대신 보이는 조작 영역으로 포커스 이동
- 뒤로·앞으로 이동, 앵커 새로고침·직접 진입
- 키보드 본문 바로가기, reduced motion
- 390px에서 루트 글꼴 200% 확대: 가로 넘침 없음, 메뉴와 연락 안내 이동 가능
- touch context의 실제 `tap()`으로 메뉴 열기·프로젝트 이동

200% 검사는 **루트 글꼴 확대**입니다. 실제 브라우저 UI의 페이지 줌이나 실기기 터치 테스트를 대신하지 않습니다. `tap()`도 Chromium의 터치 에뮬레이션입니다.

## 검사에서 발견하고 수정한 결함

1. **320px 앵커 새로고침 복원:** React가 영역을 만들기 전에 브라우저가 해시 목적지를 찾는 시점 문제와 진행 중인 부드러운 스크롤을 정리했습니다. 마운트 후 초기 앵커를 복원하고 기본 이동은 즉시 수행합니다. 새로고침과 직접 진입을 회귀 검사에 포함했습니다.
2. **767→768px 키보드 포커스:** CSS가 메뉴 버튼을 숨기는 순간 초점이 body로 먼저 이동하는 경합을 확인했습니다. 숨기기 직전의 실제 초점을 기억해 보이는 메뉴로 넘기며, 반대 방향과 뒤로 이동도 검사합니다.
3. **정적 검토 보완:** 원본 breadme 로고/색 계열과 보이는 이름, 로고의 접근 가능한 이름, 짧은 메뉴의 44px 너비, Node 의존성이 요구하는 24.15+ 최소 버전, 한국어 단어 단위 줄바꿈을 맞췄습니다.

첫 두 CI 실행은 결함 때문에 실패했습니다. 오류를 무시하거나 재시도 성공만으로 완료 처리하지 않았으며 수정 후 전체 검사를 다시 실행했습니다. 마지막 기능 검사 11개는 모두 첫 시도에 통과했습니다.

## 확인하지 않은 범위

- 실제 iOS Safari/Android 기기, Firefox, 화면 읽기 프로그램 종합 검수
- 브라우저 자체 줌 200%의 수동 검수
- 아직 이관하지 않은 콘텐츠·이미지·PDF·메일 기능
- 최종 디자인·콘텐츠·영어 UI·공개 승인

화면 캡처 검수와 자동 접근성 검사는 확인한 범위에 대한 근거이며 모든 기기·접근성 인증을 대신하지 않습니다.
